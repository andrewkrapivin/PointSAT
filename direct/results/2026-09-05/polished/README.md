# Short coordinate polishing runs

Every file here was exhaustively validated with `direct/verify` after polishing.
Compression preserves all labeled orientation signs. The `--seconds` values
are wall-time limits; exact iteration counts can vary with machine load.

| File | Input | Command parameters | Grid |
| --- | --- | --- | --- |
| `repair23-grid400-s12-compact.pts` | `../portfolio/repair23-grid400-s12.pts` | `compact --seconds 1 --seed 811` | 349 by 346 |
| `es32-compact.pts` | `direct/seeds/es32.pts` | `compact --seconds 2 --seed 812` | 156 by 186 |
| `es26cap5-compact.pts` | `direct/seeds/es26cap5.pts` | `compact --seconds 1 --seed 1 --preserve-x-order` | 76 by 141 |

The 23-point input comes from a repair search initialized from the published
PointSAT Figure 1 coordinates, scaled to a 400 by 400 grid. It is seeded
refinement, not a search from random coordinates. It differs from the paper's
point set in 39 of 1771 labeled orientation signs. Its 853 convex hexagons
(all nonempty) differ from the paper seed's 753; therefore these two point
sets have nonisomorphic order types. The independent canonical comparison in
`paper23_comparison.json` also confirms nonisomorphism up to relabeling and
reflection. This does not establish novelty relative to all previously known
solutions in the literature or the original PointSAT experiments.

The 32- and 26-point inputs are generated by a known Erdős–Szekeres construction,
as described in `direct/construct_notes.md`. Their existence is not new.

The 32-point compression is smaller than the 230 by 310 example illustrated
in the cited 2018 construction paper, but we have not established that it is
the smallest known integer realization.
