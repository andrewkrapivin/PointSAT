# PointSAT pipeline experiments, 5 September2026

The improved SAT-guided geometric pipeline found four independently certified
23-point order types in these runs. All have no convex7-gon and no empty6-hole,
and differ from the paper example and from one another. These are fresh-SAT
searches, not cold coordinate-only searches or proofs of a new extremal bound.
The native benchmark team found another distinct23-point type separately.

## Controlled orchestration comparison

Eight identical SAT models (seeds0–7), identical flippable sets, native seed1,
the same immutable upstream Localizer, two single-thread workers, and15seconds
per realization were used on both sides. The empty `-f` and `-c` files avoid
undefined upstream argument-pointer behavior consistently on both sides.

| Pipeline | Wall seconds | CPU seconds | Valid samples |
|---|---:|---:|---:|
| Original |91.945|179.932|0/8|
| Improved Python/helpers |79.791|156.726|0/8|

This is13.2% less wall time and12.9% less CPU in one paired run on a shared,
loaded machine. It is not an estimate of native search speed or a statistically
established success-rate improvement. Full settings and raw outputs are in
[paired_pipeline/manifest.json](paired_pipeline/manifest.json).

The changes include persistent per-process SAT checking, exact flippability
screening supplied by the root helper, model caching, removal of redundant
scranfilize calls during realization, strict SAT-status parsing, deterministic
retries, bounded child-process cleanup, and explicit stage timings.

## Search treatments

The initial feedback pilot matched four SAT models per family and allowed up to
four15-second native attempts per model. Core-guided feedback releases actual
orientation assumptions from UNSAT cores, solves for a nearby abstract target,
and warm-starts the native solver. Failed coordinate search never produces a
heuristic permanent SAT exclusion.

|23-point treatment|Wall seconds|Native worker seconds|Valid samples|
|---|---:|---:|---:|
|Ordinary warm retries|131.136|240.072|0/4|
|Core-guided retargeting|67.131|111.860|1/4|

Feedback can stop early when its SAT budget is exhausted, so actual consumed
native budgets differ. These times must not be presented as a2x speedup for an
equivalent amount of work. The first success arrived44.913seconds after the
feedback portfolio started. The same pilot found0/4 solutions for32points and
0/4 for26points in either arm. See
[feedback_pilot/manifest.json](feedback_pilot/manifest.json).

A later controlled23-point pilot matched six fresh SAT seeds5000–5005, nativev4,
archives, radial scaffold handling, and all limits. Hash-based core choice found
0/6 in157.888wallseconds (135native worker seconds); target-margin choice found
1/6 in131.223wallseconds (105native worker seconds). This is a small exploratory
result, not statistical evidence of dominance. The unattended portfolio favors
target-margin choices but preserves a hash arm.

## Negative results and safeguards

The frozen fresh corpus has five generated models each for23,26,and32points;
the29-point generation attempts with seeds9201–9205 all timed out after90seconds.
The split was frozen before outcomes, with the first two models per family for
tuning and the remaining three held out. The five29-point timeouts remain in
the manifest rather than being discarded. Later29-point trials with default
Kissat and `--sat` both timed out after180seconds. These are search-budget
failures, not UNSAT results.

The nativev6 `--ordered-x`26-point pilot found0/4 valid samples after16native
attempts and12feedback rounds, taking245.216wallseconds/245.298CPU seconds.
It produced no errors. Exact5-cap counting is mandatory before any26-point
acceptance, including archives; satisfying an orientation CNF alone is not a
sufficient coordinate certificate for a direction-dependent cap condition.

Target-aware core selection on the original mapped19-point scaffold reduced a
128-assumption unsuccessful repair to a one-primary-variable repair in the
initial comparison. Nevertheless, the subsequent730.924-second portfolio
still found no valid19-point configuration, with17native attempts and510native
worker seconds. The best target objective remained three violations. Root and
independent validation subsequently proved the retained relaxed target itself
unrealizable, explaining why this particular search target should be abandoned.
That proof does not establish nonexistence of every19-point configuration.

## Exact non-realizability cuts and unattended queue

Two independently verified positive product-inequality certificates exclude the
supplied full19-point assignment and a942-constraint relaxed target. Their
colex blocking clauses have967 and939 premise literals. Signed map projection
gives sound327- and318-literal clauses in the user's original compressed CNF.
The new file [verified19/with_two_verified_cuts.cnf](verified19/with_two_verified_cuts.cnf)
contains those clauses; the original user CNF is unchanged. Proof metadata and
hashes are in [verified19/with_two_verified_cuts.proofs.json](verified19/with_two_verified_cuts.proofs.json).

Before a native launch, the pipeline independently rechecks each certificate
and only prunes a target retaining **all** of its premises. Omitting even one
required orientation disables that pruning decision. The frozen19-point jobs
generate fresh SAT assignments from the augmented CNF, not fixed old cubes.

[unattended_20260905/jobs.json](unattended_20260905/jobs.json) contains120
oversubscribed jobs:40mixed23 and20each of symmetry19, gons32, holes29, caps26.
Every job uses one native thread and one Python process worker, with a600-second
supervisor budget (900for29points). The root supervisor owns the two-worker
launch and14:00UTC deadline, cancellation, and per-job independent audits.
Native binaries and source are frozen; `freeze.json` and
`input_provenance.json` record executable, source, configuration, proof, and
input hashes. Audit acceptance uses the original problem CNF, not merely its
proof-augmented derivative.
